Formcatch Component Library

Every component on the live site comes from this file. Copy the HTML shown under each one — that's the full "API": no build step, no JavaScript framework, just documented classes. Load components.css once per page to use any of them.

Button

Three variants, two extra sizes, a disabled state, and a loading state that keeps the accessible label intact.

Ghost link
<button class="fc-btn fc-btn--primary">Primary</button> <a href="#" class="fc-btn fc-btn--ghost">Ghost link</a> <button class="fc-btn fc-btn--primary" disabled>Disabled</button> <!-- Loading state: disable interaction with aria-busy, keep a real label for screen reader users --> <button class="fc-btn fc-btn--primary fc-btn--loading" aria-busy="true"> <span class="fc-btn__spinner" aria-hidden="true"></span> Saving… </button>

Accessibility: focus ring uses :focus-visible so it only shows for keyboard users, not mouse clicks. Never remove it — it's the only way keyboard users see what's selected.

Badge

Small status labels. Color communicates meaning — keep teal for positive/pass, amber for caution, red for errors, neutral for anything else.

PASS CAUGHT ERROR CHECK 1
<span class="fc-badge fc-badge--teal">PASS</span>

Card

The base surface for grouped content. Add --featured to highlight one option among several (e.g. a recommended pricing tier). Add --interactive only if the whole card is clickable — it adds hover/focus affordance, so don't use it on static cards.

Form field

Label, input, and an optional hint or error. The error state pairs aria-invalid on the input with role="alert" on the message so screen readers announce it immediately.

We'll only use this to contact you.

Enter a valid email address.

<div class="fc-field fc-field--error"> <label class="fc-field__label" for="email">Email</label> <input class="fc-field__input" id="email" type="email" aria-invalid="true" aria-describedby="email-err"> <p class="fc-field__error" id="email-err" role="alert"> Enter a valid email address. </p> </div>

Alert

Use role="status" for calm updates, role="alert" only for something that needs immediate attention — overusing role="alert" makes screen readers interrupt constantly.

Your form is protected.
Couldn't save — check your connection.
Free plan includes up to 200 submissions/month.
<div class="fc-alert fc-alert--error" role="alert"> Couldn't save — check your connection. </div>

Skeleton (loading)

Placeholder shapes shown while real content is being fetched. Always mark the containing region aria-busy="true" and give screen reader users a text alternative — a shimmering box alone tells them nothing.

Loading recent activity…
<div aria-busy="true"> <span class="fc-sr-only">Loading recent activity…</span> <div class="fc-skeleton" style="width:70%; height:14px;"></div> </div>

Empty state

Shown when a list has genuinely nothing in it yet — not the same as loading. Tell the person what will appear here and, if possible, what to do about it.

No submissions yet

Once your form goes live, activity will show up here.

<div class="fc-empty"> <p class="fc-empty__title">No submissions yet</p> <p class="fc-empty__body">Once your form goes live, activity will show up here.</p> </div>

Best practices used throughout

  • Every interactive element has a visible :focus-visible state — required for keyboard-only users.
  • Color is never the only signal — badges and alerts pair color with text, not color alone.
  • All animation respects prefers-reduced-motion.
  • Loading and empty states are distinct — a skeleton means "fetching," an empty state means "fetched, nothing there."
  • One spacing scale (4px steps) and one radius scale are reused everywhere — no one-off pixel values.
